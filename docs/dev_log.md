# Engineering Log & Scratchpad

This file is a living technical journal for `autonomous-prediction-pipeline`. It records architectural decisions, verification, and limits of the code that actually landed. It is not a user guide.

## Milestone 1 — Detection contracts and coordinate frames

### Log 1.1: Phase 1 header contracts and BEV projection

- **Date:** October 30, 2026
- **Objective:** Stand up a C++17 header library that can take an ego-frame detection into the world BEV plane from either a planar pose or an upstream `4 x 4` rigid transform, plus the downstream track and trajectory structs later phases will fill in.
- **What landed:**
  - `prediction_lib` is an interface library. Phase 1 has no translation units. Include path is `include/`, and the only link dependency is `Eigen3::Eigen`.
  - Warning flags live on `prediction_lib` (`-Wall -Wextra -Wpedantic -Wconversion -Wshadow`, or `/W4` on MSVC). They are not global `add_compile_options`, so fetched GoogleTest is not rebuilt under `-Wconversion`.
  - `kPi` / `kTwoPi` are `inline constexpr` in `namespace prediction`. C++17 has no `std::numbers::pi`, and `M_PI` is not standard.
  - `normalize_angle` is `atan2(sin(angle), cos(angle))`. For a finite angle this lands in `[-pi, pi]`. `+pi` and `-pi` are the same heading. Odd multiples of pi can come back as either endpoint because `sin(pi)` is a tiny residual whose sign is not stable.
  - `SE(2)` ego-to-world and world-to-ego follow the spec rotation. The pose argument is always ego-to-world, including on the inverse. Size and score are copied.
  - `SE(3)` treats the detection as a point on the ego `z = 0` plane, applies the `4 x 4`, and keeps only world `x` and `y`. Heading is `atan2` of the transformed local forward vector `[cos(psi), sin(psi), 0, 0]`, then wrapped. It is not `psi_ego + yaw(T)`. World `z` is discarded. Pitched box extents are not recomputed.
- **Rotation convention used by the pitch/roll test:** active intrinsic `R = Rz(yaw) * Ry(pitch) * Rx(roll)`, which is the same matrix as extrinsic `X` then `Y` then `Z`. The test rebuilds the expected point and forward vector from that matrix instead of trusting the function under test. The specified case uses ego heading `0`. A second assertion uses ego heading `0.35` so a wrong implementation that only adds the transform yaw cannot pass.
- **Boundary chosen for the angle test:** odd multiples of pi are checked with `abs(abs(normalized) - pi) < 1e-9`, not with a required sign. Other angles (`0`, `2 pi`, `5.5 pi -> -0.5 pi`, `-7.25 pi -> 0.75 pi`) are checked with `EXPECT_NEAR` plus sine/cosine equivalence.

### Log 1.3: Limits left in this phase

- **Date:** October 30, 2026
- `normalize_angle` is specified only for finite inputs. NaN and infinity are not mapped to a heading.
- If a transformed forward vector is exactly vertical, its BEV heading is undefined (`atan2(0, 0)`). The 10 degree roll / 5 degree pitch case does not hit that singularity, and the function does not special-case it.
- There is no `SE(3)` world-to-ego inverse. Only the planar inverse is implemented.
- `DetectionFrame` stores both `ego_pose_2d` and `ego_pose_se3`. Nothing checks that one is the planar projection of the other. Callers pick which transform to apply.
- Track and trajectory structs were contracts only at the end of Milestone 1. The single-target filter landed in Milestone 2 Phase 1. Gated association landed in Milestone 2 Phase 2. The multi-object tracker landed in Milestone 2 Phase 3. The kinematic predictor landed in Milestone 3 Phase 1 and extended `PredictedTrajectory` without reordering its original fields.

### Log 1.4: Phase 2 stream-based CSV ingestion and frame grouping

- **Date:** October 31, 2026
- **What landed:** Header-only `prediction::CsvReader(std::istream&)`, `read_next_frame`, and `load_all_frames`. No new dependencies or library target changes.
- **CSV contract:** The first nonblank line must contain the eleven schema names in order; names and numeric tokens are whitespace-trimmed. Quoted CSV fields are not supported. Invalid/missing headers permanently exhaust the reader. Input rows are assumed ordered by frame ID; grouping is consecutive, not a global merge or sort.
- **Validation:** Frame IDs are digit-only uint64 values with overflow checks. Floating-point tokens must parse completely and be finite. Malformed rows are skipped, including partial detections, trailing numeric garbage, and nonpositive box dimensions. Detection headings are normalized; ego yaw is retained as supplied. Score is retained without an additional range restriction.
- **Empty frames:** All six detection fields must individually be empty or case-insensitive `nan` to form a sentinel. Mixed empty/NaN sentinels are supported; partial sentinels are rejected. Sentinels never erase accumulated detections.
- **Grouping and poses:** Only valid rows start frames or trigger boundaries. One validated lookahead row is cached; the last frame flushes exactly once at EOF. Repeated-ID metadata must exactly equal the first valid row's timestamp and pose, otherwise the row is skipped. Each frame has consistent planar 2D and SE(3) ego-to-world poses. A false return leaves the output unchanged.
- **Tests:** Added `test_csv_reader` with 11 discovered cases covering grouping, streaming/load-all equivalence, independent SE(3) expectations, heading normalization, malformed-row recovery, full uint64 range, sentinel variants and every partial sentinel combination, metadata conflicts, and unchanged output on failure. Computed poses/angles use tolerances against independent expectations.
- **Verification:** Ran a clean rebuild followed by `cmake -B build -DCMAKE_EXPORT_COMPILE_COMMANDS=ON && cmake --build build && ctest --test-dir build --output-on-failure`. All **15/15 tests passed** (4 Phase 1, 11 Phase 2), with zero compiler warnings. Project targets retain `-std=c++17 -Wall -Wextra -Wpedantic -Wconversion -Wshadow` and compiler extensions remain disabled.

## Milestone 2 — Single-target motion model

### Log 2.1: Phase 1 6D Kalman filter

- **Date:** November 2, 2026
- **What landed:** Header-only `prediction::KalmanFilter` and `KalmanFilterConfig` in `include/prediction/kalman_filter.hpp`. No new dependencies. `tests/kalman_filter_linkage.cpp` includes the same header from a second translation unit so an ODR break would fail the link of `test_kalman_filter`.
- **State and model:** State remains the Milestone 1 contract `[x, y, v_x, v_y, psi, omega]`. Predict is constant velocity plus constant turn rate. Those blocks are decoupled on purpose. A coordinated-turn model would rotate `(v_x, v_y)` by `omega * dt`; this one does not. Heading is directed and `2 pi` periodic. Box orientation with a `pi` ambiguity is not handled here.
- **Process noise name:** The specified `(1/4) dt^4`, `(1/2) dt^3`, `dt^2` blocks are discrete piecewise-constant white acceleration noise, with variances in `m^2/s^4` and `rad^2/s^4`. They are not the continuous-time white-noise integrals `(1/3) dt^3`, `(1/2) dt^2`, `dt`. Subdividing a predict interval changes the accumulated `Q`. For `dt > 0`, each of the three noise blocks has rank 1, so `Q` has three positive eigenvalues and three exact zeros.
- **Failure contract:** The constructor throws `std::invalid_argument` unless all eight variances are finite and `> 0`. `initialize` returns `std::nullopt` for a detection that fails the shared checks: finite position, heading, and score, and both size components finite and `> 0`. Score is not clipped to `[0, 1]`, matching `CsvReader`. `predict` and `update` return `false` without writing the track when `dt` is non-finite or negative, the track is not admissible, the detection is invalid, an LDLT of `S` is not strictly positive definite, or a computed matrix is non-finite. `dt == 0` on an admissible track returns `true` and does not rewrite state, covariance, size, id, or status, including an unnormalized heading.
- **Admissibility:** State, covariance, and size must be finite, both size components must be `> 0`, and covariance must be symmetric to `1e-9 * (1 + max(|Pij|, |Pji|))`. Positive-semidefinite input is checked with `SelfAdjointEigenSolver`: the smallest eigenvalue may be negative only by `1e-9 * (1 + max(0, lambda_max))`. A singular covariance is allowed. That check is not used as a substitute for a positive-definite `S`.
- **Update numerics:** `S` must report `LDLT` success, `isPositive()`, finite `vectorD()`, and every pivot strictly greater than zero. The gain is `ldlt.solve((P H^T).transpose()).transpose()`. The covariance write is the Joseph form, then `P = 0.5 (P + P^T)`. Squared Mahalanobis distances in `[-1e-12, 0)` are clamped to zero; anything more negative or non-finite is rejected. `update` does not apply a gate, and neither `predict` nor `update` writes `track_id` or `status`.
- **Caller obligations:** Measurements are assumed world-frame. Nothing in `Detection` can prove that. Heading evolution between updates must not be aliased by more than `pi`, or the wrapped residual will pull turn rate the wrong way.
- **Tests:** Initialization and config rejection; independent `F`/`Q` propagation; velocity and turn-rate convergence over 40 steps; predict and update crossing the `+/- pi` cut, with the update prior loose enough that the posterior actually crosses; covariance shrinkage, symmetry, and positive eigenvalues on a well-conditioned birth update; Mahalanobis agreement and `+2 pi` invariance; rejection of bad `dt`, bad detections, asymmetric covariance, and an indefinite covariance without mutation; second-TU linkage.
- **Verification:** `cmake -B build -DCMAKE_EXPORT_COMPILE_COMMANDS=ON && cmake --build build && ctest --test-dir build --output-on-failure` on November 2, 2026. **25/25 passed** (4 Phase 1, 11 Phase 2, 10 Kalman). The Kalman objects were compiled as `-std=c++17 -Wall -Wextra -Wpedantic -Wconversion -Wshadow` with extensions off, and that rebuild produced no warnings. A first build failed on a transposed `P H^T` (6x3 written into a 3x6 temporary); the gain path is now `solve((P H^T)^T)^T`, which is the shape `LDLT` expects.

### Log 2.2: Phase 2 gated Hungarian association

- **Date:** November 3, 2026
- **What landed:** Header-only `prediction::DataAssociation`, `DataAssociationConfig`, `TrackDetectionMatch`, `AssociationResult`, and `CostMatrix` in `include/prediction/data_association.hpp`. No new dependencies. `tests/data_association_linkage.cpp` includes the same header from a second translation unit.
- **Objective:** Maximum cardinality over gate-admissible pairs, then minimum sum of squared Mahalanobis distances. The solver is a rectangular shortest-augmenting-path Hungarian reduction, not a permutation search. Complexity is `O((M + N)^3)` arithmetic steps with `O((M + N)^2)` auxiliary storage. Cost construction is a separate `O(MN)` pass because the filter state dimension is fixed.
- **Normalization:** A threshold merely larger than `G` does not guarantee maximum cardinality. An augmenting path can exchange several cheap matches for one more expensive match. Every admissible cost is therefore divided by `G`, placing it in `[0, 1]`. Each of the `M` tracks receives one private dummy column at cost `P = min(M, N) + 1`. A matching with `k` real pairs then costs somewhere in `[(M - k) P, (M - k) P + min(M, N)]`. Those intervals do not overlap, so gaining one match beats every possible reduction in the real-cost sum. The reported `mahalanobis_distance_sq` remains the unnormalized filter value. This also avoids forming a penalty such as `(K + 1) G`, which can overflow for a large threshold.
- **Forbidden edges:** A pair whose distance is `nullopt`, non-finite, or strictly greater than `G` is absent from the augmenting-path search. It is not encoded as a large finite number. The scan never lets a forbidden edge erase or replace the slack of another column. Zero-size default tracks and detections inherit the filter's existing rejection and stay unmatched. An asymmetric or indefinite covariance does the same. Valid pairs in the same call are still assigned, and neither input is mutated.
- **Gate and ties:** Acceptance is `d2 <= G` with no epsilon. Equality is deliberately inside the gate. Equal-cost assignments are deterministic for a fixed input because the Dijkstra frontier and column scans always advance in increasing index order. That tie break is not documented as the lexicographically smallest matching; it is only required to be repeatable.
- **Empty shapes:** `CostMatrix` stores `track_count` and `detection_count` independently of the row-major cost vector, so `0 x N` and `M x 0` remain distinguishable. Both short-circuit before the solver. `solve_cost_matrix` rejects a size mismatch and any present cost that is negative or non-finite.
- **Caller obligations:** Association does not call `predict`, does not transform detections, and does not inspect `TrackStatus`. A caller that wants association at a future time must predict first and pass the predicted tracks. Measurements must already be world-frame.
- **Tests:** Invalid thresholds; a 2x2 anti-greedy reversal; a 3x3 case where three matches require giving up two cheap edges; exact gate equality and a value just outside; `M < N`, `M > N`, both empty shapes, and a fully gated-out pair; malformed tracks and detections beside one valid pair; wrapped-heading agreement with the filter; repeatable equal-cost assignment; direct matrix validation; second-TU linkage.
- **Verification:** `cmake -B build -DCMAKE_EXPORT_COMPILE_COMMANDS=ON && cmake --build build && ctest --test-dir build --output-on-failure` on November 3, 2026. **35/35 passed**, including the 10 new association tests. The data-association objects compiled as `-std=c++17 -Wall -Wextra -Wpedantic -Wconversion -Wshadow` with extensions off. The build emitted no warnings.

### Log 2.3: Phase 3 multi-object tracker and lifecycle

- **Date:** November 6, 2026
- **What landed:** Header-only `prediction::MultiObjectTracker`, `TrackerConfig`, `TrackRecord`, `TrackOutputPolicy`, and `PoseSource` in `include/prediction/tracker.hpp`. No new dependencies. `types.hpp` is unchanged: `TrackState` still has no counters or timestamps. `tests/tracker_linkage.cpp` includes the same header from a second translation unit.
- **Storage:** Live state is two vectors, `tracks_` and `records_`, compacted together and kept in ascending `track_id` order. `tracks_` is passed to `DataAssociation::associate` directly. A parallel record avoids copying the track list into the associator and avoids adding bookkeeping fields to the shared track contract. IDs start at 1. ID 0 is never assigned. A pruned ID is not reused until `reset()`, which restarts the counter.
- **One predict per frame:** `dt` is this frame's timestamp minus the previous accepted timestamp, or 0 on the first frame after construction or `reset()`. Each live track is predicted once. `state_time` advances to the frame timestamp on success. Predicting from `last_hit_time` instead would apply the same coast twice, once when the miss happened and again when the track is touched later. It would also change the covariance, because the piecewise-constant white-acceleration model is not invariant to splitting a step.
- **Promotion at birth:** `initialize` always starts the track as `Tentative`. The same promotion check used after a later hit runs before the track is appended. `min_hits_to_confirm == 1` therefore publishes a `Confirmed` track from the birth frame. A `Lost` track that is hit returns to `Confirmed` immediately; it does not have to rebuild the confirmation streak.
- **Prune before birth:** Predict failures are removed before association, so a non-admissible track cannot take an index the associator will use. Misses, including a matched update that returns false, are marked and compacted after the hit/miss pass and before births. A newborn is not eligible for either prune, so this has the same surviving set as pruning after birth. Doing it first keeps the step-5 and step-6 indices valid.
- **Filter failure policy:** A failed `predict` marks the track and removes it immediately. A failed `update` is a miss: consecutive hits clear, the miss counter increments, `Confirmed` becomes `Lost`, and the usual prune limits apply. The coasted state is the prediction already applied. A failed `initialize` skips that detection and does not consume an ID.
- **Frame validation:** `frame_id` must strictly increase. Timestamp must be finite and non-decreasing; an equal timestamp is a real frame with `dt = 0` and still counts as a hit. Only the pose selected by `pose_source` is required to be finite. The unused pose is not read. The first frame after construction or `reset()` accepts any id and any finite timestamp. Every check runs before a member is written, so a rejected frame has the strong guarantee, including the previous `process_frame` output buffer. A duplicate frame would otherwise increment hits and move the lifecycle without any new time.
- **Exceptions after validation:** `std::bad_alloc`, and the assignment solver's `std::logic_error` if it cannot find a feasible assignment, have only the basic guarantee. Prediction, updates, pruning, or a partial birth may already have happened. History is written only after births, so a throw during birth leaves the previous frame id and timestamp in place.
- **Allocation profile:** `tracks_`, `records_`, `world_detections_`, `prune_flags_`, and `output_` are members. The constructor reserves 64 entries. `clear()` and in-place compaction keep that capacity, so a warmed-up `process_frame` does not allocate for those buffers. `DataAssociation::associate` still allocates its cost matrix, accepted-distance vector, result vectors, and Hungarian scratch arrays on every call. That is unchanged from Phase 2. A workspace overload on the associator would be the way to remove it; it is not in this phase.
- **Future enhancements (out of scope):** A minimum detection score before birth. Time-based coast pruning, because a miss count means a different physical time at a different frame rate, and a low-rate `Lost` track grows a gate wide enough to attach to an unrelated detection. Two-stage association, `Confirmed` and `Lost` before `Tentative`, because one max-cardinality Hungarian pass can spend a `Lost` track's detection on a clutter-born `Tentative` track.
- **Decisions not covered by the spec:**
  - Frame-validation exceptions name the field (`DetectionFrame::timestamp`, `frame_id`, `ego_pose_2d`, `ego_pose_se3`), matching the `TrackerConfig::` messages the spec requires. The spec only required the tracker-field messages.
  - `reset()` also zeroes `last_frame_id_` and `last_timestamp_`. They are unread while `has_last_frame_` is false.
  - `next_track_id_` is not checked for `uint64_t` overflow. Wrapping would eventually assign ID 0, which this tracker otherwise never assigns.
  - Before births, `tracks_` and `records_` are both reserved to `size + unmatched_detections.size()`. A `bad_alloc` can then come only from a `reserve`, before any append, so the two vectors never differ in size. A size mismatch would not be "basic guarantee": the next frame indexes `records_` with `tracks_` indices, which would be out of bounds.
  - An unknown `TrackOutputPolicy` value, which a well-formed enum class cannot produce, publishes no tracks. The switch has no default so a new enumerator is a compile error.
  - The shallow-crossing check allows a 1e-9 m slack when asking which ground-truth vehicle is nearer. On the single frame where both vehicles occupy the same point, position cannot show a swap; the heading residual is what keeps the assignment, and the frames on either side still separate the tracks.
- **Crossing geometry:** 50 frames at 0.1 s. Vehicles at 10 m/s heading 0 and 11 m/s heading 25 degrees both pass through the origin at frame 25. Drops are frames 8, 16, 24, and 40 for the first vehicle and 12, 25, 33, and 46 for the second: 8 of 100 slots, with one drop on the frame before the intersection and one on the intersection frame. No geometry change was required.
- **Verification:** From a fresh `build/` directory, `cmake -B build -DCMAKE_EXPORT_COMPILE_COMMANDS=ON && cmake --build build && ctest --test-dir build --output-on-failure` on November 6, 2026. **52/52 passed** (4 ingestion, 11 CSV, 10 Kalman, 10 association, 17 tracker). The tracker objects compiled as `-std=c++17 -Wall -Wextra -Wpedantic -Wconversion -Wshadow` with extensions off. The build log contained no warning lines.

## Milestone 3 — Kinematic prediction

### Log 3.1: Phase 1 constant-speed multimodal predictor

- **Date:** November 10, 2026
- **What landed:** Header-only `prediction::KinematicTrajectoryPredictor` and `PredictorConfig` in `include/prediction/predictor.hpp`. `TrajectoryPoint` and `TrajectoryMode` were added to `types.hpp`. `PredictedTrajectory` kept `track_id`, `current_state`, and `waypoints` in that order and gained `modes`. No new dependencies. `tests/predictor_linkage.cpp` includes the same header from a second translation unit.
- **Why the output type changed:** The proposal's `TrajectoryPoint` / `TrajectoryMode` types were not the Milestone 1 contract, and `PredictedWaypoint` has no velocity. Removing `waypoints` or `current_state` would have been a silent break. Predictor output fills both. `modes` is authoritative. `waypoints` copies the straight mode without velocity, so that mode is stored twice. A default trajectory still has no modes; emptiness is not an error sentinel.
- **Motion model:** World velocity is not reconstructed from speed and heading. That would change a valid tracker state such as `(v_x, v_y) = (10, 0)` with `psi = pi/2`. Straight motion is `p0 + t v0`. A turn with rate `r` is `v(t) = R(r t) v0` and `p(t) = p0 + t sinc(r t / 2) R(r t / 2) v0`. Heading uses the same rate after one normalization of `psi0`, so the initial heading/velocity offset is preserved. The labels are geometric: positive is counterclockwise, negative is clockwise. They are not overtake and yield intents, and the rollout has no acceleration, so it is not CTRA.
- **Rates:** Straight is exactly 0. Left is `max(omega, branch)`, right is `min(omega, -branch)`, with `branch > 0`. This is a minimum signed rate, not `omega +/- branch`. Setting `omega` to 0 does not make a turn mode singular under the default branch of 0.15. The small-angle path keys off `|r t / 2| < 1e-4`, using `1 - z^2/6 + z^4/120`, because a tiny rate over a long horizon can still be a large turn.
- **Standstill:** Both velocity components must be exactly zero. All three modes then hold position and the normalized heading and emit zero velocity, even if `omega` is nonzero. A nonzero creep is rolled out. There is no 0.1 m/s threshold.
- **Time grid:** `N = round(H / dt)`, checked before the integer cast and capped at 10000 per track. Sample times are `current_timestamp + m * dt` for `m = 1..N`, computed from the index rather than accumulated. The realized horizon can miss `H` by about half a step. `0.15 / 0.1` is not a binary half-tie; the half-tie test uses `1.5 / 1`. Finite timestamps that collapse to a non-increasing grid throw `std::overflow_error` rather than being nudged with `nextafter`.
- **Covariance:** `C(t) = P_pp + t^2 P_vv + q t I`, shared by every mode. `q` is already m^2/s and is not squared. This is an uncertainty envelope, not the turn-model covariance: cross blocks and heading/turn-rate uncertainty are absent. Input covariance uses the filter's symmetry and PSD tolerances, including singular PSD. Only a tolerance-level negative eigenvalue is lifted to zero, and the caller's matrix is not rewritten. Output is symmetrized and must remain PSD within that tolerance. Strict diagonal growth is not promised.
- **Failures:** Config and malformed tracks throw `std::invalid_argument` with the field name. A batch names `batch index` as well. Nonfinite computed positions, velocities, headings, covariances, and timestamps throw `std::overflow_error`. Timestamp and every track are checked before a batch result is built, so an invalid track cannot leak a prefix. Inputs are not mutated. Track status is not filtered; a `Lost` state is forecast from the supplied instant and is not coasted again.
- **Allocation:** Return by value owns nested vectors, so a workspace cannot make this API allocation-free. Known lengths are reserved or resized up front. Per-track complexity is `O(N)` with the mode count fixed at 3.
- **Probabilities:** A sum within `1e-6` of 1 is accepted and then divided by the actual sum. `config()` exposes those normalized weights. They are mixture weights, not calibrated probabilities.
- **Tests:** Config rejection and a nonfinite `H / dt`; straight velocity preservation, including sideways and reverse motion with a disagreeing heading; independent circular integrals and a quarter-turn radius; tiny branch rates at `omega = 0` and `+/- 1e-12`; the sinc series switch; mirror symmetry; `max`/`min` branch thresholds; heading wrap; exact standstill and creep; the covariance formula, shared modes, singular zero growth, and a clamped `1e-12` eigenvalue; malformed tracks without mutation; nonfinite output and collapsed timestamps; rounded future grids; status, duplicate IDs, empty and rejected batches; one tracker-produced `Lost` track; second-TU linkage.
- **Verification:** `cmake -B build -DCMAKE_BUILD_TYPE=Release -DCMAKE_EXPORT_COMPILE_COMMANDS=ON && cmake --build build && ctest --test-dir build --output-on-failure` on November 10, 2026. **73/73 passed** (52 existing, 21 predictor). `tests/CMakeFiles/test_predictor.dir/flags.make` records `-O3 -DNDEBUG -std=c++17 -Wall -Wextra -Wpedantic -Wconversion -Wshadow`. The predictor rebuild emitted no warning lines.

### Log 3.2: Phase 2 minADE / minFDE / miss-rate evaluator

- **Date:** November 17, 2026
- **What landed:** Header-only `prediction::TrajectoryEvaluator`, `MetricsConfig`, `TrajectoryMetrics`, and `BatchMetricsSummary` in `include/prediction/metrics.hpp`. `GroundTruthWaypoint` and `GroundTruthTrajectory` were appended after `PredictedTrajectory` in `types.hpp`. No predictor, field-order, or prior-test changes. No new dependencies. `tests/metrics_linkage.cpp` includes the evaluator header from a second translation unit. `predictor.hpp` is included only by the integration test.
- **Independent minima:** ADE is the unweighted arithmetic mean of `std::hypot(dx, dy)` in waypoint order, not RMS and not time-weighted. FDE is the last distance. `min_ade` and `min_fde` are selected separately and can name different modes. The first scored mode seeds both, including a largest-finite score. A later mode replaces a winner only on a strict improvement, so an exact computed tie keeps the earliest mode. `is_miss` is `min_fde > miss_threshold_meters`; equality is a hit.
- **What is not read:** Probability, velocity, heading, covariance, `current_state`, and the legacy `waypoints` view are not inspected, even to validate them. Corrupt values there do not change a score. Conversely, a non-finite position in a later mode still rejects the pair after a perfect earlier mode. The implementation does not assume `K = 3` and does not drop modes.
- **Alignment:** Ground truth is validated once. Each mode must have exactly `N` points, with strictly increasing finite timestamps of its own. The absolute timestamp difference at each shared index must be `<= timestamp_tolerance`. That bound is inclusive and absolute; zero means exact equality. Nothing is sorted, interpolated, truncated, or resampled. `max - (-max)` is not a finite double, so opposite-sign extremes fail alignment even when the configured tolerance is `numeric_limits<double>::max()`. Negative timestamps and a one-point trajectory are valid. There is no inferred current time.
- **Overflow:** Component differences, hypot, per-mode sums, and batch sums of the per-pair minima are checked in input order. A non-finite difference, distance, or sum throws `std::overflow_error`, including a sum in a mode that cannot win. The sum is not replaced by an online mean, and the code does not use `long double`. A large but representable hypot is a score, not an error. Division by `N` happens only after the checked sum. Batch means divide the checked pair-sum by an explicit `double` pair count. Misses are counted as integers and then divided in floating point. One bad pair rejects the batch; inputs are not mutated.
- **Batch shape:** Empty or unequal lengths throw `std::invalid_argument` before scoring. Pairs are positional, not joined by ID, so duplicate and unsorted IDs stay in input order and a crossed-ID batch is a rejection rather than a reorder. Different pairs may have different `N` and `K`. The summary averages one minimum per pair, not per waypoint.
- **Allocation:** Scoring uses a constant number of scalars per pair besides the returned `per_track` vector, which is reserved once. Work is linear in the samples inspected. Inline member definitions are safe to include from more than one translation unit.

- **Projection:** `X = W/2 + (x - c_x) s`, `Y = H/2 - (y - c_y) s`. Width, height, and the camera center may be fractional. All numeric SVG text uses `std::locale::classic()`. Geometry keeps the default 17-digit stream precision; HUD text uses a separate 3-digit fixed format. `kPi` is the angle constant.
- **What is not consumed:** A track's `6 x 6` covariance and a prediction's embedded `current_state` are not read, so they are not Kalman-validated. Vehicle boxes come only from `tracks`. Nonempty `modes` are authoritative and the legacy `waypoints` copy is ignored, including when that copy is non-finite. Empty `modes` with nonempty legacy waypoints is drawn as one forecast. That is a rendering convenience, not an evaluator fallback. Empty collections and any `K` are valid.
- **Covariance:** Gross off-diagonal asymmetry above `1e-9 * (1 + max(|a|, |b|))` is rejected. Accepted roundoff is averaged as `a/2 + b/2` so the sum cannot overflow. `Eigen::SelfAdjointEigenSolver<Eigen::Matrix2d>` supplies ascending eigenvalues; the last one is the major axis. `lambda_min < -1e-9 * (1 + max(0, lambda_max))` is rejected. Accepted negative roundoff is clamped to zero. The matrix is normalized before the solve when its largest absolute entry exceeds 1, then the eigenvalues are scaled back. Semi-axes are `sigma * sqrt(lambda) * pixels_per_meter`. Screen angle is `atan2(-v_y, v_x) * 180 / pi`, folded into `(-90, 90]`. An exactly isotropic pair uses `0`. Angles that differ by 180 degrees are the same ellipse. Zero rank is omitted because a zero SVG radius is invisible. Rank one is a centered segment of length `2 * sigma * sqrt(lambda_max) * s`. Contours are documented as n-sigma, not 95 percent. Every authoritative covariance is solved during validation, including skipped stride samples and frames with `draw_covariance_ellipses = false`.
- **Boxes and arrows:** The rectangle and nose live in a local group translated to the projected center and rotated by `-yaw_deg`. Length is local `+x`. The velocity arrow is outside that group, from the projected position to the projection of `p + tau v`. Zero world velocity, `tau = 0`, or a tip that collapses to the center omits the arrow. Heading and velocity are independent.
- **Grid:** Lines sit on world multiples of the spacing, not on the camera. The visible index range is `ceil(first / spacing)` through `floor(last / spacing)`, counted in double before any integer cast. Either axis above 2048 lines, or a window whose index is non-finite, omits the whole grid and leaves a comment. There is no `value += spacing` walk, and no geographic index is required to fit in `int`.
- **Layers and labels:** Stable group ids are `background`, `grid`, `ground_truth`, `uncertainty`, `predictions`, `tracks`, `labels`, `hud`. A one-point path is a circle. An empty path emits nothing. Candidate offsets that overlap the HUD or an earlier label are skipped. The score line is dropped first. If nothing fits, the label is omitted and the frame still returns.
